# Урок 1. Введение в DevOps и Linux-сервер

## Цель урока
Понять, что такое DevOps, научиться подключаться к удаленному серверу по SSH и освоить базовые команды навигации по файловой системе Linux.

## Что потребуется для этого урока
* **Терминал** (встроенный в вашу ОС: Terminal в Linux/macOS, PowerShell или WSL в Windows).
* **Сервер** (на этом уроке можно обойтись без него, но для следующих уроков он понадобится). 
  Подойдет любой из вариантов:
  * **Облачный VPS** (арендованный у провайдера).
  * **Реальный физический сервер** (например, старый компьютер или Raspberry Pi).
  * **Локальная виртуальная машина** (VirtualBox или VMware с установленной Ubuntu Server).
* **Базовые навыки работы с клавиатурой** (терминал не любит мышь).

## Теория

### 1. Что такое DevOps?
DevOps — это методология, которая объединяет разработку (Dev) и эксплуатацию (Ops). 
Раньше программисты писали код, а системные администраторы разворачивали его на серверах вручную. Это приводило к задержкам и ошибкам. 
DevOps-инженер автоматизирует процесс доставки кода на сервер, настраивает инфраструктуру и следит за стабильностью работы приложения.

### 2. Что такое сервер и VPS?
Сервер — это компьютер, который работает круглосуточно и доступен через интернет (или локальную сеть). 
VPS (Virtual Private Server) — это виртуальный сервер в облаке. Вы арендуете часть мощностей у провайдера, получаете IP-адрес и доступ по паролю или ключу.

### 3. Подключение по SSH
SSH (Secure Shell) — протокол безопасного удаленного доступа к серверу.
Чтобы подключиться, нужна программа-клиент (в Linux и macOS это встроенный терминал, в Windows — PowerShell или PuTTY).

Команда для подключения:
~~~bash
ssh user@ip_address
~~~
* `user` — имя пользователя (обычно `root` или `ubuntu`).
* `ip_address` — IP-адрес вашего сервера.

При первом подключении система спросит: 
**Are you sure you want to continue connecting?** 
*Перевод: «Вы уверены, что хотите продолжить подключение?»*

Введите `yes` и нажмите Enter. После этого появится сообщение:
**Warning: Permanently added 'IP-адрес' (ED25519) to the list of known hosts.**
*Перевод: «Предупреждение: IP-адрес навсегда добавлен в список известных хостов».*

Теперь ваш компьютер запомнил этот сервер, и при следующих подключениях это предупреждение появляться не будет.

### 4. Файловая система Linux
В Linux нет дисков `C:` или `D:`. Вся файловая система начинается с корня `/`.
* `/` — корень.
* `/home` — домашние папки пользователей (ваши личные файлы).
* `/etc` — конфигурационные файлы системы и программ.
* `/var/log` — логи (журналы событий).

### 5. Права доступа и sudo
В Linux не принято работать от имени суперпользователя (`root`) постоянно, потому что можно случайно сломать систему.
Вместо этого вы работаете от обычного пользователя, а для опасных операций (установка программ, редактирование системных файлов) используете команду `sudo` (SuperUser DO).
~~~bash
sudo apt update
~~~
Эта команда выполнит `apt update` с правами администратора.

### 6. Пакетный менеджер (apt)
В Linux программы не скачивают с сайтов в виде `.exe` файлов. Вместо этого используются **пакетные менеджеры** — специальные утилиты, которые сами находят программу в репозиториях, скачивают её, устанавливают и обновляют зависимости.

В нашем курсе мы будем использовать сервер на **Ubuntu** (это стандарт для большинства облачных серверов). В Ubuntu и Debian используется пакетный менеджер **APT** (Advanced Package Tool).

Основные команды:
* `sudo apt update` — обновить список доступных пакетов из интернета. Выполнять перед установкой чего-либо.
* `sudo apt install имя_пакета` — установить программу. Например, `sudo apt install nginx`.
* `sudo apt remove имя_пакета` — удалить программу.

**Важно для локальной работы:**
Если вы отрабатываете команды не на удаленном сервере, а на своем компьютере, названия команд могут отличаться в зависимости от вашей операционной системы:
* **Fedora / CentOS / RHEL:** вместо `apt` используется `dnf` (например, `sudo dnf install nginx`).
* **macOS:** используется менеджер `brew` (например, `brew install nginx`).
* **Windows:** лучше всего установить WSL (Windows Subsystem for Linux) и работать в нем как в Ubuntu.

В дальнейшем все команды в курсе будут даваться для Ubuntu (`apt`), так как это целевая среда для развертывания.

## Практика
Для выполнения заданий этого урока вам понадобится **Linux-среда**. 

Вы можете выбрать любой удобный вариант:
* **Локальная виртуальная машина** (VirtualBox или VMware с установленной Ubuntu Server) — если вы работаете на Windows или macOS.
* **WSL** (Windows Subsystem for Linux) — если вы на Windows 10/11. Это встроенный в Windows Linux, который позволяет работать с командами без установки полноценной виртуальной машины.
* **Облачный VPS** или **физический сервер** — если они у вас уже есть.
* **Ваш основной компьютер**, если на нем установлен Linux (например, Fedora или Ubuntu).

*Важно:* стандартный терминал Windows (PowerShell или CMD) **не подойдет** для команд этого курса, так как в Windows другая файловая система (диски `C:`, `D:`) и другие команды.
