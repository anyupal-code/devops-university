# Урок 4. Веб-сервер Nginx и обратный прокси

## Цель урока
Понять, зачем нужен веб-сервер Nginx, научиться настраивать обратный прокси (Reverse Proxy) для Java-приложения и подключать доменное имя.

## Что потребуется для этого урока
* **Сервер** (облачный VPS, локальная виртуальная машина или физический сервер с ОС Ubuntu).
* **Запущенное Java-приложение** (из прошлых курсов) на порту `8080`.
* **Домен** (опционально). Если домена нет, можно использовать IP-адрес сервера.

---

## Теория

### 1. Что такое Nginx?
**Nginx** (произносится «энджинкс») — это популярный веб-сервер и обратный прокси. 
Он работает как «парадная дверь» для вашего сервера:
* Принимает все входящие HTTP-запросы из интернета (на порты 80 и 443).
* Раздает статические файлы (картинки, CSS, HTML) очень быстро.
* Перенаправляет запросы к вашему приложению (например, написанному на Java).

**Обратный прокси** (Reverse Proxy) — это программа, которая стоит перед вашим приложением и перенаправляет к нему запросы.

### 2. Зачем нужен обратный прокси?
Ваше Java-приложение (Spring Boot) запущено на порту `8080`. Но если пользователь зайдет на `http://ваш-ip:8080`, это выглядит непрофессионально. Кроме того, порт `8080` не защищен HTTPS.

**Обратный прокси** решает эту проблему:
1. Пользователь заходит на `http://my-site.com` (порт 80).
2. Nginx принимает запрос и перенаправляет его на `http://localhost:8080` (где работает Java).
3. Пользователь не знает, что внутри используется порт 8080.

### 3. Установка Nginx
В Ubuntu установка выполняется одной командой:
~~~bash
sudo apt update
sudo apt install nginx
~~~
После установки Nginx автоматически запустится и будет слушать порт 80. Если вы откроете IP-адрес сервера в браузере, увидите стандартную страницу «Welcome to nginx!».

### 4. Конфигурация Nginx
Все настройки хранятся в файлах `/etc/nginx/`. 
Главный конфигурационный файл — `/etc/nginx/nginx.conf`, но для каждого сайта лучше создавать отдельные файлы в `/etc/nginx/sites-available/` и делать на них ссылку в `/etc/nginx/sites-enabled/`.

Пример конфигурации для обратного прокси:
~~~nginx
server {
    listen 80;
    server_name my-site.com;  # Или IP-адрес сервера

    location / {
        proxy_pass http://localhost:8080;  # Куда перенаправлять
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
~~~

### 5. Управление Nginx
* `sudo systemctl start nginx` — запустить.
* `sudo systemctl stop nginx` — остановить.
* `sudo systemctl restart nginx` — перезапустить (после изменения конфигурации).
* `sudo nginx -t` — проверить конфигурацию на ошибки (обязательно перед перезапуском!).

### 6. HTTPS (SSL-сертификаты)
Чтобы сайт работал по `https://`, нужен SSL-сертификат. Самый простой способ — использовать **Let's Encrypt** и утилиту **Certbot**.

~~~bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d my-site.com
~~~
Certbot автоматически получит сертификат и настроит Nginx на использование HTTPS (порт 443).
