# Задания к Уроку 12

## Задание 1. Подготовка сервера
1. Убедитесь, что на вашем сервере установлены Docker и Docker Compose.
2. Создайте папку для проекта: `mkdir ~/backend-app && cd ~/backend-app`.
3. Скопируйте туда `docker-compose.yml` (из прошлых уроков).
4. Убедитесь, что Nginx настроен как обратный прокси на порт 8080 (или на порт контейнера).

## Задание 2. Настройка SSH-доступа
1. Сгенерируйте ключ: `ssh-keygen -t ed25519 -C "github-actions"` (нажимайте Enter, чтобы не задавать пароль).
2. Скопируйте публичный ключ на сервер: `ssh-copy-id user@ip_сервера`.
3. Проверьте, что можете зайти на сервер без пароля: `ssh user@ip_сервера`.

## Задание 3. Добавление секретов в GitHub
В настройках репозитория (`Settings -> Secrets and variables -> Actions`) добавьте:
* `SSH_PRIVATE_KEY` — содержимое файла `~/.ssh/id_ed25519` (приватный ключ).
* `SSH_HOST` — IP-адрес сервера.
* `SSH_USER` — имя пользователя.
* `SSH_PORT` — порт (обычно `22`).

## Задание 4. Добавление шага деплоя в workflow
1. Откройте `.github/workflows/docker-publish.yml` (из урока 9).
2. Добавьте после шага сборки и пуша новый шаг (из теории):

~~~yaml
    - name: Deploy to Server
      uses: appleboy/ssh-action@v1.0.0
      with:
        host: ${{ secrets.SSH_HOST }}
        username: ${{ secrets.SSH_USER }}
        key: ${{ secrets.SSH_PRIVATE_KEY }}
        port: ${{ secrets.SSH_PORT }}
        script: |
          cd ~/backend-app
          docker-compose pull
          docker-compose up -d
          docker system prune -f
~~~

3. Сделайте коммит и пуш. Убедитесь, что workflow прошел успешно.

## Задание 5 (*). Проверка полного цикла
1. Внесите любое изменение в код (например, добавьте новый эндпоинт или измените текст).
2. Сделайте коммит и пуш.
3. Подождите 1–2 минуты.
4. Обновите страницу приложения. Убедитесь, что изменения применились автоматически.

**Ожидаемый результат:** после пуша GitHub Actions собрал новый образ, отправил его на сервер, обновил контейнеры, и сайт показал новую версию.
