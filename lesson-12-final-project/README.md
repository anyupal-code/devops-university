# Урок 12. Итоговый проект: Полный цикл CI/CD

## Цель урока
Объединить все полученные знания (Docker, Nginx, GitHub Actions, мониторинг) в одном проекте, настроив автоматическую доставку кода на сервер.

## Что потребуется для этого урока
* **Сервер (VPS)** с установленным Docker и Nginx.
* **Репозиторий на GitHub** с Java-проектом (Spring Boot).
* **Docker Hub** (или GitHub Container Registry) для хранения образов.
* **Настроенный мониторинг** (Prometheus + Grafana) с прошлого урока.

---

## Теория

### 1. Архитектура проекта
Итоговый проект представляет собой полный конвейер доставки:
1. **Разработчик** пушит код в GitHub.
2. **GitHub Actions** запускает тесты и сборку.
3. Собирается **Docker-образ** и публикуется в Docker Hub.
4. На **сервере** запускается скрипт, который скачивает новый образ и перезапускает контейнеры.
5. **Nginx** (на сервере) принимает запросы и перенаправляет их на приложение.
6. **Prometheus + Grafana** собирают метрики с приложения и сервера.

### 2. Автоматизация деплоя (CD)
В прошлых уроках мы собирали образ, но не доставляли его на сервер. Для этого используется **Continuous Deployment**.
Есть два способа:
* **Push-модель:** GitHub Actions заходит на сервер по SSH и выполняет команды.
* **Pull-модель:** На сервере работает скрипт (или Watchtower), который периодически проверяет обновления в Docker Hub и скачивает их.

Мы реализуем **Push-модель** через GitHub Actions (самый популярный способ для небольших проектов).

### 3. Настройка SSH-доступа в GitHub Actions
Чтобы GitHub Actions мог зайти на ваш сервер, нужно добавить приватный SSH-ключ в секреты репозитория:
1. Сгенерируйте ключ на локальной машине: `ssh-keygen -t ed25519 -C "github-actions"`.
2. Публичный ключ (`id_ed25519.pub`) добавьте в `~/.ssh/authorized_keys` на сервере.
3. Приватный ключ (`id_ed25519`) скопируйте в секреты GitHub под именем `SSH_PRIVATE_KEY`.
4. Также добавьте секреты `SSH_HOST` (IP сервера), `SSH_USER` (имя пользователя) и `SSH_PORT` (обычно 22).

### 4. Пример шага деплоя в GitHub Actions
~~~yaml
    - name: Deploy to Server
      uses: appleboy/ssh-action@v1.0.0
      with:
        host: ${{ secrets.SSH_HOST }}
        username: ${{ secrets.SSH_USER }}
        key: ${{ secrets.SSH_PRIVATE_KEY }}
        port: ${{ secrets.SSH_PORT }}
        script: |
          cd /path/to/project
          docker-compose pull
          docker-compose up -d
          docker system prune -f
~~~

* `appleboy/ssh-action` — готовое действие для выполнения команд на удаленном сервере.
* `docker-compose pull` — скачивает новые образы из Docker Hub.
* `docker-compose up -d` — перезапускает контейнеры с новыми образами.
* `docker system prune -f` — очищает старые образы (чтобы не забивать диск).

### 5. Проверка работы
После пуша в `main`:
1. GitHub Actions собирает и пушит образ.
2. Заходит на сервер и обновляет контейнеры.
3. Через минуту сайт (Nginx) уже показывает новую версию приложения.
