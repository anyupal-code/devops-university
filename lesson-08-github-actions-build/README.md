# Урок 8. GitHub Actions: Тесты и сборка

## Цель урока
Научиться создавать workflow (конвейер) в GitHub Actions, который автоматически собирает и тестирует Java-проект при каждом пуше.

## Что потребуется для этого урока
* **Репозиторий на GitHub** с Java-проектом (Spring Boot или любой Maven-проект).
* **Файл `pom.xml`** в корне проекта.

---

## Теория

### 1. Где хранятся конфигурации GitHub Actions?
GitHub Actions ищет файлы конфигурации в папке `.github/workflows/` в корне вашего репозитория. 
Каждый файл в этой папке с расширением `.yml` (или `.yaml`) — это отдельный **workflow** (конвейер). 
Имя файла может быть любым (например, `build.yml`, `test.yml`).

### 2. Структура workflow
Workflow состоит из трех основных частей:
1. **`name`** — название конвейера (отображается в интерфейсе GitHub).
2. **`on`** — события, которые запускают конвейер (например, `push` в ветку `main`).
3. **`jobs`** — задачи, которые выполняются на виртуальной машине.

Пример:
~~~yaml
name: Java CI

on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
    - uses: actions/checkout@v4
    - name: Set up JDK 21
      uses: actions/setup-java@v4
      with:
        java-version: '21'
        distribution: 'temurin'
    - name: Build with Maven
      run: mvn -B clean package --file pom.xml
~~~

### 3. Разбор ключевых элементов
* **`runs-on: ubuntu-latest`** — GitHub предоставляет виртуальную машину с Ubuntu для выполнения задачи.
* **`steps`** — последовательность шагов.
* **`uses`** — использование готового действия (action) из маркетплейса. 
  * `actions/checkout@v4` — копирует код из вашего репозитория на виртуальную машину.
  * `actions/setup-java@v4` — устанавливает нужную версию JDK.
* **`run`** — выполняет команду в терминале виртуальной машины.
* **`-B`** — флаг Maven (batch mode), отключает интерактивные запросы и делает вывод более читаемым.

### 4. Кэширование зависимостей
Скачивание зависимостей Maven при каждом запуске может занимать много времени. GitHub Actions позволяет кэшировать папку `.m2/repository`.

Добавьте шаг кэширования перед сборкой:
~~~yaml
    - name: Cache Maven packages
      uses: actions/cache@v4
      with:
        path: ~/.m2
        key: ${{ runner.os }}-m2-${{ hashFiles('**/pom.xml') }}
        restore-keys: ${{ runner.os }}-m2
~~~

* `key` — уникальный ключ кэша. Если `pom.xml` не изменился, кэш будет использован повторно.

### 5. Просмотр результатов
После пуша в GitHub:
1. Перейдите на страницу репозитория.
2. Откройте вкладку **Actions**.
3. Вы увидите запущенный workflow (желтый кружок — выполняется, зеленый — успех, красный — ошибка).
4. Нажмите на него, чтобы увидеть логи каждого шага.
