# Урок 2. Сети для разработчика

## Цель урока
Понять, как работает передача данных по сети, что такое IP-адреса, порты и DNS, и почему локальный сервер не виден из интернета.

## Что потребуется для этого урока
* **Терминал** (локальный или подключение к серверу по SSH).
* **Утилиты для проверки сети** (`ping`, `curl`, `ss`), которые уже встроены в Linux.

---

## Теория

### 1. IP-адрес
IP-адрес — это уникальный числовой адрес устройства в сети (как адрес дома). 
Есть две версии:
* **IPv4:** `192.168.1.1` (4 числа от 0 до 255).
* **IPv6:** `2001:0db8:85a3:0000:0000:8a2e:0370:7334` (длиннее, новый стандарт).

Адреса бывают:
* **Внешние (публичные):** видны во всем интернете.
* **Внутренние (локальные):** видны только в вашей домашней или офисной сети (например, `192.168.x.x` или `10.x.x.x`).

### 2. Порты
Один IP-адрес может использоваться для множества программ одновременно. Чтобы они не мешали друг другу, используются **порты** (числа от 0 до 65535).
* `80` — HTTP (обычные сайты).
* `443` — HTTPS (защищенные сайты).
* `22` — SSH (удаленное подключение к серверу).
* `5432` — PostgreSQL.
* `8080` — часто используется для тестовых веб-приложений (например, нашего Java-бэкенда).

Пример: `192.168.1.1:8080` означает «подключись к IP `192.168.1.1` по порту `8080`».

### 3. DNS
Людям сложно запоминать IP-адреса, поэтому придумали **DNS** (Domain Name System).
DNS — это «телефонная книга» интернета. Когда вы вводите `google.com`, компьютер спрашивает у DNS-сервера: «Какой IP-адрес у `google.com`?» — и получает ответ (например, `142.250.190.46`).

### 4. Локальный сервер и localhost
Когда вы запускаете приложение на своем компьютере, оно по умолчанию доступно только внутри этого компьютера.
* `localhost` (или `127.0.0.1`) — это всегда ваш текущий компьютер.
* Если вы запустили Java-приложение на порту `8080` и открыли в браузере `http://localhost:8080`, браузер подключится к вашему же компьютеру.

**Почему это не видно в интернете?**
Ваш компьютер находится за **NAT** (маршрутизатором). У вас есть внутренний IP (например, `192.168.1.5`), но нет публичного (внешнего) IP. Чтобы приложение стало доступно извне, нужен публичный IP (например, на облачном сервере) и настройка проброса портов или обратного прокси (Nginx).

### 5. Утилиты для диагностики
В Linux есть встроенные команды для проверки сети:
* `ping google.com` — проверить, есть ли связь с сервером (отправляет пакеты и ждет ответа).
* `curl http://localhost:8080` — отправить HTTP-запрос и получить ответ (без браузера).
* `ss -tulnp` — показать, какие порты сейчас слушаются на компьютере и какие программы их используют.
