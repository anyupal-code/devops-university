# Теория: Сети и оркестрация в Docker Compose

## 1. Сетевая изоляция
Docker Compose по умолчанию создает изолированную сеть (bridge network) для всех сервисов проекта. Контейнеры в этой сети могут обращаться друг к другу по именам сервисов (DNS-разрешение внутри Docker).

## 2. Порядок запуска (depends_on)
Деректива `depends_on` управляет порядком запуска контейнеров, но не гарантирует готовность сервиса. Если приложение запустится быстрее базы данных, оно может упасть. Для надежности используются механизмы healthcheck и политики перезапуска (`restart: always`).

## 3. Управление секретами
Передача паролей через переменные окружения (`environment`) небезопасна, так как они могут быть видны в логах или при инспекции контейнера. Использование `secrets` позволяет монтировать файлы с паролями внутрь контейнера, не сохраняя их в образе.
