# Теория: Принципы мониторинга и метрики

## 1. Задачи мониторинга
Мониторинг в DevOps предназначен для решения трех задач:
1. **Наблюдаемость (Observability):** понимание внутреннего состояния системы на основе внешних данных (логов, метрик, трассировок).
2. **Оповещение (Alerting):** автоматическое уведомление администратора при выходе показателей за допустимые пределы.
3. **Анализ тенденций:** выявление проблем с производительностью до того, как они приведут к сбою.

## 2. Метрики (Metrics)
Метрика — это числовой показатель, характеризующий работу системы в конкретный момент времени.
Основные типы метрик:
* **Counter (Счетчик):** значение только увеличивается (например, количество HTTP-запросов).
* **Gauge (Датчик):** значение может изменяться в обе стороны (например, использование оперативной памяти).
* **Histogram (Гистограмма):** распределение значений по заданным диапазонам (например, время ответа на запрос).
* **Summary (Сводка):** аналогична гистограмме, но вычисляет квантили на стороне клиента.

## 3. Модель Pull и Push
В системах мониторинга используются два подхода сбора данных:
* **Pull (Вытягивание):** сервер мониторинга (Prometheus) периодически сам запрашивает метрики у приложений по HTTP.
* **Push (Отправка):** приложение само отправляет метрики на сервер (используется реже, например, при работе за NAT).

## 4. Стек Prometheus и Grafana
* **Prometheus** — база данных временных рядов (Time Series Database). Он собирает метрики (Pull), хранит их и позволяет выполнять запросы на языке PromQL.
* **Grafana** — инструмент визуализации. Подключается к Prometheus как источник данных и строит графики и дашборды.
* **Node Exporter** — агент, который собирает системные метрики (CPU, RAM, диск) с сервера и отдает их Prometheus.

## 5. Архитектура сбора
1. Node Exporter (или приложение) предоставляет метрики по эндпоинту `/metrics`.
2. Prometheus раз в N секунд запрашивает этот эндпоинт (Scrape).
3. Данные сохраняются в базе.
4. Grafana запрашивает данные из Prometheus и отображает их на графиках.
