# Теория: Архитектура итогового проекта

## 1. Назначение
Итоговый проект демонстрирует полный цикл DevOps: от написания кода до автоматического деплоя на сервер с последующим мониторингом.

## 2. Компоненты системы
Проект состоит из следующих элементов:
* **Java-приложение (Spring Boot):** Бэкенд с REST API.
* **База данных (PostgreSQL):** Хранилище данных.
* **Nginx:** Обратный прокси, принимающий запросы из интернета и перенаправляющий их на приложение.
* **Docker Compose:** Инструмент для локального запуска всех компонентов.
* **GitHub Actions:** CI/CD-конвейер для сборки, тестирования и публикации образов.
* **Prometheus + Grafana:** Система мониторинга.

## 3. Схема взаимодействия
1. Пользователь отправляет HTTP-запрос на домен.
2. **Nginx** (на сервере) принимает запрос на порт 80/443 и перенаправляет его на контейнер с Java-приложением (порт 8080).
3. **Java-приложение** обрабатывает запрос и обращается к **PostgreSQL** за данными.
4. **Prometheus** собирает метрики с приложения и сервера.
5. **Grafana** отображает метрики на дашборде.

## 4. Процесс CI/CD
1. Разработчик делает `git push` в ветку `main`.
2. **GitHub Actions** запускает тесты и сборку.
3. Собирается Docker-образ и публикуется в реестр (Docker Hub или ghcr.io).
4. На сервере выполняется команда `docker-compose pull && docker-compose up -d` (обновление контейнеров).
5. Prometheus и Grafana продолжают мониторинг обновленного приложения.

## 5. Критерии готовности
Проект считается завершенным, если:
* Приложение доступно по домену (или IP) без указания порта 8080.
* При каждом пуше в `main` запускается GitHub Actions и успешно собирает образ.
* Grafana отображает живые графики загрузки CPU и памяти.
* Все компоненты запускаются одной командой `docker-compose up -d`.
