# Теория: Реестры Docker-образов и публикация

## 1. Реестр Docker (Docker Registry)
Реестр — это серверное хранилище для Docker-образов. Он позволяет хранить, версионировать и распространять образы. 
При выполнении команды `docker pull` клиент обращается к реестру, чтобы скачать образ, а при `docker push` — загружает его.

## 2. Публичные и приватные реестры
* **Docker Hub** — крупнейший публичный реестр (по умолчанию). Образы здесь доступны всем.
* **GitHub Container Registry (ghcr.io)** — реестр, встроенный в GitHub. Удобен для CI/CD, так как использует ту же авторизацию, что и репозиторий.
* **Приватные реестры** — используются для корпоративных проектов (например, Nexus, Harbor) и требуют авторизации для доступа.

## 3. Тегирование образов (Tags)
Тег — это метка, привязанная к конкретной версии образа (например, `my-app:v1.0`). 
Теги бывают:
* **Фиксированные** (например, `v1.0.0`) — однозначно указывают на версию.
* **Плавающие** (например, `latest`) — указывают на последнюю версию, но могут привести к неожиданностям при обновлении.

Для CI/CD рекомендуется использовать фиксированные теги (например, хэш коммита или номер версии), чтобы сборка была воспроизводимой.

## 4. Аутентификация
Для отправки образов в реестр необходима аутентификация. 
* В GitHub Actions для этого используется встроенный токен `GITHUB_TOKEN`, который автоматически создается при запуске workflow.
* Для Docker Hub требуются логин и пароль (или Personal Access Token), которые сохраняются в **Secrets** репозитория (Settings -> Secrets and variables -> Actions).

## 5. Этапы публикации
1. Сборка образа (`docker build`).
2. Присвоение тега (`docker tag`).
3. Аутентификация в реестре (`docker login`).
4. Отправка образа (`docker push`).
