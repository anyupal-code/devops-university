# Теория: Внутреннее устройство Docker

## 1. Контейнеризация и виртуализация
Виртуальная машина (VM) эмулирует физическое оборудование и требует полноценной гостевой ОС. 
Контейнер использует ядро хост-системы и изолирует процессы с помощью механизмов Linux (namespaces и cgroups). Это делает контейнеры легковесными и быстрыми.

## 2. Слои образа (Layers)
Docker-образ состоит из слоев. Каждая инструкция в `Dockerfile` (RUN, COPY) создает новый слой. Слои доступны только для чтения и кэшируются. При изменении кода пересобираются только последние слои, что ускоряет сборку. Многоэтапная сборка (Multi-stage build) позволяет исключить из финального слоя компилятор и исходный код.

## 3. Изоляция (Namespaces и Cgroups)
* **Namespaces** обеспечивают изоляцию (контейнер видит только свои процессы, сеть и файловую систему).
* **Cgroups** (Control Groups) ограничивают потребление ресурсов (CPU, память). Настройка лимитов в `docker-compose.yml` управляет именно cgroups.

## 4. Тома (Volumes)
Поскольку файловая система контейнера эфемерна (удаляется вместе с контейнером), для сохранения данных используются тома. Том — это директория на хост-системе, монтируемая в контейнер.
